## 1. Назначение и решаемая проблема

При исследовании незнакомых кодовых баз или подготовке контекста для больших языковых моделей (ChatGPT, Claude, Cursor) разработчики сталкиваются с двумя крайностями:

1. **Ручной отбор файлов** — тратит время, легко упустить транзитивную зависимость (типы, утилиты, доменные модели).
2. **Передача проекта целиком («context dump»)** — раздувает окно контекста LLM, тратит токены, снижает точность ответов («lost in the middle») и превышает лимиты контекста.

**CodeMap** решает эту проблему прямо в браузере:
- Строит интерактивный граф связей файлов на базе React Flow и автоматической послойной компоновки ELK.js.
- Позволяет выбрать любой модуль и мгновенно увидеть его входящие и исходящие зависимости.
- Выполняет обход подграфа зависимостей с устранением дубликатов и генерирует готовый Markdown-контейнер для промпта нейросети в один клик.
- Находит потенциальных кандидатов на рефакторинг по настраиваемому порогу строк кода (Lines of Code).

Проект работает **на 100% на клиенте**, не требует собственного бэкенда, БД или API-ключей и оптимизирован для публикации на **GitHub Pages**.

## 2. Ключевые возможности

- **Автоматическая укладка топологии (ELK.js):** Граф модулей автоматически ранжируется по слоям (`layered`), исключая спутанные соединения и хаотичное расположение узлов.
- **Двусторонняя синхронизация дерева и графа:** Выбор файла в проводнике подсвечивает его в графе, и наоборот.
- **Изоляция подграфа файла:**
  - Синие анимированные рёбра — прямые исходящие импорты файла.
  - Зеленые анимированные рёбра — входящие зависимости (модули, использующие данный файл).
  - Несвязанные файлы и рёбра визуально приглушаются.
- **Инспектор кода и метаданных:** Правая панель отображает реальный исходный код модуля, количество строк, список импортов с возможностью перехода в один клик и экспортируемые идентификаторы.
- **Контекст для LLM с дедупликацией:**
  - Алгоритм обхода в ширину (BFS) гарантирует, что каждый зависимый файл включается в результирующий Markdown ровно один раз.
  - Оценка примерного числа токенов и объема исходного кода.
  - Копирование в буфер обмена с fallback для браузеров с ограниченным `navigator.clipboard`.
- **Поиск кандидатов на рефакторинг:** Настраиваемый слайдер порога строк (по умолчанию 500 LOC) мгновенно подсвечивает громоздкие файлы в проекте.

## 3. Архитектура интерактивного демо

В демонстрационный стенд встроен полностью рабочий проект каталога напитков (`drink-catalog`) из **ровно 10 TypeScript-файлов**:

```text
src/
├── main.ts                      # Входная точка приложения
├── app.ts                       # Компоновка DI и инициализация сервисов
├── config.ts                    # Глобальные константы и параметры пагинации
├── routes/
│   └── drinks.ts                # HTTP/API роутеры
├── services/
│   └── drinkService.ts          # Доменная бизнес-логика
├── repositories/
│   └── drinkRepository.ts       # Хранилище в памяти
├── models/
│   └── drink.ts                 # Сущность напитка с валидацией
├── utils/
│   └── normalize.ts             # Утилиты форматирования цен и строк
├── components/
│   └── drinkCard.ts             # Компонент рендеринга карточки
└── types.ts                     # Базовые доменные типы и интерфейсы
